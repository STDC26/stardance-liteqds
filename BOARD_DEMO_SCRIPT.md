# QDS Lite Product MVP — Board Demo Script

**Tag:** `qdslite-product-mvp-recovery-v1`
**Branch:** `u1-uat`
**Runtime:** `npm run product:dev` → `http://localhost:4320`
**Duration:** Under 5 minutes

---

## Setup (30 seconds)

```bash
git checkout u1-uat
npm install
npm run product:dev
```

Open `http://localhost:4320` in browser.

---

## Demo Flow

### 1. Landing (15 seconds)

- Show the QDS Lite landing screen
- Point out: "Experimental Lite surface" badge, trust disclaimer, two entry points
- Click **Browse QDS flows**

### 2. Gallery — Preset Flows (30 seconds)

- Show three preset QDS flows: Stardance Growth Fit, Docente Learning Fit, VMG Adaptation Readiness
- Point out: question count, pathway count, Preset badges
- "These were created without code changes — purely from the QDSDefinition schema"
- Click **Stardance Growth Fit QDS** to run it

### 3. Intake — Running a QDS (60 seconds)

- Walk through the 6 questions
- Point out: progress bar, auto-advance, back button
- Answer to produce a "Strong Fit" result (pick growth-stage, product-led, dedicated resources, mature infra, immediately, budget approved)

### 4. Result — Governed Output (45 seconds)

- Show the governed qualification card
- Point out the governance signal strip: "Lite · experimental", "Not authorized for runtime", "Human review required"
- Point out the directional confidence read (word-label, never a number)
- Point out trust surface limitations (always visible, expandable)
- Point out the verdict options with routing summaries
- Show the lead capture CTA form
- "This entire card was generated by the same LiteQDS substrate that powers the internal review harness — same governance, same fail-closed behavior"

### 5. Builder — Creating a New QDS (90 seconds)

- Navigate back to Gallery, click **+ Create new QDS**
- Show cognition guidance callout on the first step ("Start with clarity")
- Fill in: Name = "Partner Technical Readiness QDS", Audience = "Integration partners", Objective = "Determine partner readiness for technical integration"
- Advance to Pathways — show guidance ("Design clear outcomes")
- Add two pathways: "Integration Ready" and "Needs Foundation"
- Advance to Questions — show guidance ("Signal, not surveys")
- Add one question: "How mature is your API infrastructure?" with answers "Production APIs" (weight 3/0) and "No APIs yet" (weight 0/3)
- Advance to CTA & Trust — show guidance ("Trust and handoff")
- Click **Review & Save**

### 6. Readiness Review (30 seconds)

- Show the 9-check quality gate
- Point out pass/warn/fail indicators
- "Question count" will warn (only 1 question) — "this is a quality suggestion, not a blocker"
- Show governance badges at bottom
- Click **Save & run** to immediately enter the new QDS intake

### 7. Library Operations (30 seconds)

- Navigate back to Gallery
- Show the new custom QDS alongside presets
- Demonstrate **Duplicate** on a preset
- Demonstrate **Edit** on the custom QDS
- "Every QDS in this library produces governed results through the same substrate — no code changes required"

---

## Key Messages

1. **Governed at the core.** Every QDS result is produced by `generateLiteQDSPanel` — the same substrate that enforces `human_review_required: true`, `runtime_authorization: not_authorized`, and fail-closed behavior.

2. **Configurable at pace.** New QDS flows are created through a guided builder with cognition guidance — no engineering required.

3. **Trust boundaries are visible.** Governance signals, trust limitations, and recourse paths are rendered on every result card and cannot be hidden.

4. **Quality-gated.** The Readiness Review checks signal quality, governance compliance, and CTA completeness before any QDS goes live.

5. **Three pathways demonstrated.** Stardance, Docente, and VMG each have distinct qualification flows with different questions, pathways, and CTAs — all from the same engine.
